# Domain documentation

This repository uses a single shared documentation layout:

- `GLOSSARY.md`: project terminology.
- `docs/adr/`: architecture decision records.

Before exploring an area of the code, read the glossary and any
relevant decision records if they exist.

If they do not exist, proceed without creating placeholders or
treating their absence as a problem. Create documentation only
when an actual need or design decision arises, with user approval.

Use terminology consistently with the glossary.

If a proposed change contradicts an existing decision record,
explain the conflict before changing the implementation.
